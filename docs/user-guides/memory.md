# 角色与剧情记忆

## 使用

重启应用后，在「设置 → 记忆管理」选择会话。记忆类型包括用户资料、偏好、共同经历、关系、约定、剧情状态和物品。

- 默认每累计 4 个完整轮次，或新增记录达到约 6000 字符后，后台整理一次。用户明确说「记住」会提前整理。整理调用当前配置的模型，会产生额外模型用量；正常回复无需等待整理完成。
- 「立即整理 / 重试」会处理当前已保存、尚未整理的完整轮次。失败时保留原始记录和处理进度，下次输入或手动重试时再尝试，不连续自动重试请求。
- 每条自动记忆带原始轮次出处。资料和偏好还会核验用户原话；没有可验证引用的提取结果进入「待核实」，不会用于回复。模型判断仍可能出错，可以在此纠正。
- 修改后点击「保存 / 确认内容」立即保存；可以固定、修改范围和知情角色，将约定标记为完成或取消。待核实内容确认后请选择「有效」。
- 「本轮使用的记忆」展示最近一次检索选中的记忆。请求总预算仍可能进一步裁剪上下文。
- 后台完成后列表自动刷新；正在编辑时不会覆盖未保存的内容，可保存后刷新。

## 继承和隔离

会话管理的新建选项有：

1. 全新剧情：使用自己的记忆，不带入旧剧情和关系。
2. 延续相处：可以检索同一角色的长期记忆。
3. 接续选中存档：复制已保存的聊天记录与技能选择，创建独立存档；原存档不变。新存档可以重新整理自己的记忆。

自动提取的经历、关系、物品归入角色长期记忆；资料、偏好、当前状态、约定默认留在本存档。角色长期记忆只有在选择继承时才会跨存档使用。用户可手动修改范围。

全局资料只能通过管理页明确设为「全局共享资料」，且接收会话需要勾选「使用我明确共享的全局资料」。固定记忆不会绕过范围和知情角色检查。角色配置中的 `memory_id` 在保存时保留，正常改名不会丢失关联。

## 重试、回溯和删除

- 停止的回复保留已显示内容，但不会自动产生长期记忆。
- 重试会撤销被替换回复的剧情事实；仍有效的用户资料与偏好可以保留用户原话作为来源。
- 回溯会使之后的来源失效，恢复较早的有效记忆版本，并重新整理摘要；后台任务会核对存档版本，不能把旧结果写回已回溯的存档。
- 清空会话同时清空其记忆、摘要和原始轮次副本；删除存档会移除对应记忆。其他存档不变。
- 删除单条记忆会保留删除标记，阻止从相同旧来源再次提取同类事实，即使改写主题名称也不会恢复。原始聊天仍然保留，近期上下文仍可能包含当时的原话。要移除原话，需要清空或回溯相应聊天记录。
- 为避免自由文本摘要复述已删除事实，有删除标记的存档停用旧摘要和后续自由文本摘要，仍可使用有效的独立记忆与近期对话。
- 「重新构建」保留手动修改、固定记忆、删除标记及重试保留的用户事实，从现有原始记录重新整理自动记忆。旧版本已经丢失的记录不能恢复。

## 数据与上下文

原始模型消息和显示历史继续保存在 `data/chat_history/sessions/*.json`。记忆、原始轮次副本、摘要分块和来源关系保存在 `data/chat_history/memory.sqlite3`，已加入 Git 忽略规则。备份时应同时备份会话文件、索引和此数据库；建议退出应用后备份。

压缩只影响发送给模型的临时上下文，不再替换完整消息历史。最近消息按完整用户轮次保留，工具调用和结果一起保留；工具循环中的每次请求也会重新核对预算。计数是带余量的估算，使用 `api.max_context_tokens` 并为回复和工具定义预留空间。单轮本身超过预算时提示缩小输入，避免截断工具调用。

旧会话按现有文件惰性导入，不在启动时批量调用模型。检索采用本地类型、范围、中文二字词与英文关键词匹配，再按相关度、重要性、未完成约定和固定状态排序；暂不使用向量模型或外部数据库。每次最多召回 12 条，另有长度预算。
