# 角色模板与控制 token 用户指南

角色模板用于约束 LLM 输出，使运行时能把普通台词、旁白、选项、资料卡、数值提示和 CG 生成请求分发到对应的 UI 处理逻辑。聊天背景由用户手动选择，背景音乐功能已移除。

## 输出格式

角色模板输出必须是一行一个 JSON 对象。不要在 JSON 外输出解释、Markdown、编号或代码块。

基本字段：

- `character_name`：说话者名称。普通对话填写角色名；控制行为填写控制 token。
- `speech`：台词、提示文本、选项文本或 CG 文生图 prompt。
- `sprite`：角色立绘编号；普通对话中 `"-1"` 表示不切换。

普通角色对话示例：

```json
{"character_name":"小夏","speech":"早上好！今天也一起努力吧。","sprite":"1"}
```

实际回复时仍应每个对象独占一行；代码块只用于本文档展示。

## 控制 token 表

| token | 用途 | `speech` 用法 | `sprite` 边界 |
| --- | --- | --- | --- |
| `COT` | 内部思考 | 填简短思考内容；默认不显示给玩家，通常只用于调试输出 | 通常填 `"-1"`；建议少量使用 |
| `NARR` | 旁白/叙述 | 填环境描写、动作叙述等旁白文本 | 通常填 `"-1"`，显示为旁白 |
| `CHOICE` | 玩家选项 | 用 `/` 分隔 2-4 个选项，例如 `去教室/去天台/留在原地` | 通常填 `"-1"` |
| `STAT` | 系统/数值变化 | 填系统提示或数值变化文本，例如 `好感度 +1` | 通常填 `"-1"`，显示为系统消息 |
| `CARD` | 资料卡 | 填 Markdown 正文，用于步骤、代码、资料和来源链接；不会被朗读 | 通常填 `"-1"` |
| `CG` | 触发 CG 文生图 | 填文生图 prompt；启用 ComfyUI 时会提交生成，未启用时只显示 `[CG]` | 通常填 `"-1"` |

不确定是否该使用控制 token 时，优先使用普通角色名，避免误触发 CG 或系统消息逻辑。玩家可以选择选项、使用“自定义回复”，或点击选项框右上角“跳过”收起整组选项。

## 手动背景与旧 token 兼容

- 在「设置 → 背景设置」添加、命名图片并选择当前背景，点击「保存配置」生效。
- 聊天过程中，点击顶栏的图片按钮打开背景选择；选择后会立即保存并应用，也可以选择「无背景」恢复透明背景。这不会发送聊天消息或调用模型。
- `SCENE`、`bgm` / `BGM` 仅保留兼容解析，聊天运行时会忽略这些旧控制 token；即使旧模板或历史中有 `sprite` / `asset_id`，也不会执行背景切换或音乐播放。新模板无需输出它们。
- 背景音乐功能已移除。角色在台词中描述场景变化，也不会自动更换背景图片。

## CG 示例

```json
{"character_name":"CG","speech":"夕阳下的教室，暖色光线，galgame 背景","sprite":"-1"}
```

说明：

- `speech` 是发送给文生图后端的 prompt。
- 当 `t2i_provider: comfyui` 且 ComfyUI 可用时，程序会把 prompt 提交给 ComfyUI 生成图片。
- 未启用 ComfyUI 或 `t2i_provider: none` 时，不会提交生成，只会在聊天区显示 `[CG]` 提示。

## 多对象输出示例

下面示例包含内部思考、旁白、角色台词、CG 请求和选项。实际输出时不要包含解释文字，只输出 JSON 行：

```json
{"character_name":"COT","speech":"玩家刚进入黄昏场景，可以先营造气氛，再给出行动选择。","sprite":"-1"}
{"character_name":"NARR","speech":"夕阳从窗边斜斜落下，教室里只剩粉笔灰在光里漂浮。","sprite":"-1"}
{"character_name":"小夏","speech":"你看，今天的天空颜色很漂亮。要不要再陪我待一会儿？","sprite":"2"}
{"character_name":"CG","speech":"夕阳下的教室，少女站在窗边回头微笑，暖色光线，galgame CG","sprite":"-1"}
{"character_name":"CHOICE","speech":"陪她待一会儿/询问她的心事/提议一起回家","sprite":"-1"}
```

## 常见错误与修正示例

错误示例可复制到“校验示例输出”文本框或命令行校验工具中，用于观察校验报错；修正示例可作为合法 JSON-lines 参考。校验器只会提示错误和警告，帮助你定位问题；它不会自动修复模板输出。

### 1. 把多行 JSON 写成数组

错误示例：外层是一个 JSON 数组，不是一行一个 JSON object。

```json
[{"character_name":"NARR","speech":"门外传来雨声。","sprite":"-1"},{"character_name":"小夏","speech":"我们等雨停再走吧。","sprite":"1"}]
```

修正示例：每个对象独占一行，不要加数组外壳。

```json
{"character_name":"NARR","speech":"门外传来雨声。","sprite":"-1"}
{"character_name":"小夏","speech":"我们等雨停再走吧。","sprite":"1"}
```

### 2. 缺少必填字段或 `character_name` 为空

错误示例：第一行缺少 `sprite`；第二行的 `character_name` 为空。

```json
{"character_name":"小夏","speech":"你好。"}
{"character_name":"","speech":"没有说话者。","sprite":"-1"}
```

修正示例：每行都包含 `character_name`、`speech`、`sprite`，且 `character_name` 非空。

```json
{"character_name":"小夏","speech":"你好。","sprite":"1"}
{"character_name":"NARR","speech":"走廊里安静下来。","sprite":"-1"}
```

### 3. `CHOICE` 选项过少、过多或出现空选项

错误示例：第一行只有 1 个有效选项；第二行有 5 个选项；第三行末尾 `/` 会留下空选项，容易导致选项数量不符合要求或输出不符合预期。

```json
{"character_name":"CHOICE","speech":"留在原地","sprite":"-1"}
{"character_name":"CHOICE","speech":"去教室/去天台/去图书馆/去操场/回家","sprite":"-1"}
{"character_name":"CHOICE","speech":"调查窗边/","sprite":"-1"}
```

修正示例：用 `/` 分隔 2-4 个非空选项。

```json
{"character_name":"CHOICE","speech":"留在原地/走向门口","sprite":"-1"}
{"character_name":"CHOICE","speech":"去教室/去天台/去图书馆/回家","sprite":"-1"}
{"character_name":"CHOICE","speech":"调查窗边/询问小夏","sprite":"-1"}
```

### 4. 控制 token 写错大小写或写成未定义 token

错误示例：`CHOICES` 是未知全大写 token，校验器会给 warning；`cg` 不是 `CG`，通常不会触发 CG 文生图逻辑。

```json
{"character_name":"CHOICES","speech":"留下/离开","sprite":"-1"}
{"character_name":"cg","speech":"雨夜街道，霓虹灯，galgame CG","sprite":"-1"}
```

修正示例：使用控制 token 表中定义的准确写法。

```json
{"character_name":"CHOICE","speech":"留下/离开","sprite":"-1"}
{"character_name":"CG","speech":"雨夜街道，霓虹灯，galgame CG","sprite":"-1"}
```

### 5. 把 CG prompt 放进 `sprite`

错误示例：`CG` 的 `speech` 为空，文生图 prompt 被误放到 `sprite`，校验器会给 warning。

```json
{"character_name":"CG","speech":"","sprite":"夕阳下的教室，少女站在窗边，galgame CG"}
```

修正示例：`speech` 填 prompt，`sprite` 通常填 `"-1"`。

```json
{"character_name":"CG","speech":"夕阳下的教室，少女站在窗边，galgame CG","sprite":"-1"}
```

## 校验示例输出

开发者可使用 `core.messaging.template_output_validator.validate_template_output(text)` 校验示例输出块。它会检查每行 JSON 对象、必填字段、`CHOICE` 选项数量，并提示疑似未知控制 token 或 CG prompt 放错字段等问题。

在设置页的“角色管理”标签中，也可以先在 `示例类型` 中选择 `完整示例`、`基础对话`、`情绪切换示例`、`CG 示例` 或 `剧情分支示例`，再点击 `填入示例` 自动生成对应 JSON-lines 示例并立即校验通过；需要自定义时，再修改文本框内容并点击 `校验示例输出`，页面会显示通过、警告或逐行错误信息，便于模板作者快速调整示例；需要转发或留存时，可点击 `复制结果` 复制当前校验结果。发布或交接前，还可以点击 `发布前检查`，汇总当前角色名称、角色设定、情绪标签和示例输出校验结果；生成的报告可复制给 reviewer/subagent 复核，也可作为模板发布前记录留存。

### 发布前检查的修复建议

`发布前检查` 会汇总当前的角色名称、角色设定、情绪标签以及 JSON-lines 示例输出校验结果。若报告发现阻断错误或警告，会在汇总之后追加 `修复建议：`，方便直接按提示调整；检查通过时不会显示修复建议。

| 检查发现的问题 | `修复建议：` 中的处理方式 |
| --- | --- |
| 角色名称为空 | 填写角色名称，例如 `小芽`。 |
| 没有示例输出 | 点击 `填入示例` 生成 JSON-lines 后再按需修改。 |
| 示例输出缺少 `sprite` | 补齐 `sprite`；若本行不切换立绘，可填 `"-1"`。 |
| 角色设定为空或过短 | 补充角色性格、称呼方式和对话边界。 |
| 情绪标签为空 | 补充例如 `0: neutral`、`1: happy` 的情绪标签。 |
| `CG` 的 prompt 被放进 `sprite` | 把 CG prompt 放到 `speech`，并将 `sprite` 设为 `"-1"`。 |

点击 `保存配置` 时会复用同一份发布前检查报告：存在严重错误时会取消保存并显示错误；只有警告时仍会保存，不会阻止保存，但页面会提示继续查看发布前检查并参考修复建议。

### 模板发布前交接清单

完成示例输出和发布前检查后，建议使用设置页的 `生成发布清单` 做本地轻量交接：点击后，结果区域会生成 copy-friendly 的 `角色模板发布清单`，方便 reviewer 或后续维护者快速复核模板意图、校验结果与控制 token 覆盖情况。

`角色模板发布清单` 会汇总：

- `角色名称`；未填写时会标为未填写。
- `角色设定`长度（按当前角色设定文本统计字数）。
- `情绪标签`行数。
- `示例输出`行数。
- `控制 token 覆盖`，按 `NARR`、`CHOICE`、`STAT`、`CG` 的固定顺序列出当前示例中覆盖到的控制 token。
- `发布前检查`状态：通过、有警告或未通过。
- `发布前检查摘要`，包含具体错误/警告以及 `修复建议：`，便于不重新运行检查也能看到需要补齐的字段、角色设定或 CG prompt 位置。

建议交接流程：

1. 选择最接近用途的 `示例类型`，点击 `填入示例`，再按角色设定改写 JSON-lines。
2. 点击 `校验示例输出`，先修严重错误，再处理警告；若有 `修复建议：`，按建议补齐字段、角色设定或 CG prompt / `speech` 位置。
3. 点击 `发布前检查`，确认角色名称、角色设定、情绪标签、示例输出通过，或只剩可接受警告。
4. 点击 `生成发布清单`，检查 `角色模板发布清单` 中的控制 token 覆盖、发布前检查状态与摘要；若状态为有警告或未通过，先按修复建议处理。
5. 点击 `复制结果`，把生成的 `角色模板发布清单` 随模板一起交接给 reviewer/维护者。
6. 用该模板跑一轮短聊天冒烟测试，确认普通台词、选项和控制 token 表现符合预期。

边界：这是本地轻量交接清单；不是完整模板市场、多示例管理或正式发布工作流，也不会自动发布模板。若后续要正式发布工作流，仍需模板打包、版本记录、审核状态、多示例管理等能力。

### 导出模板发布草稿

在完成 `发布前检查` 和 `角色模板发布清单` 复核后，可点击设置页角色管理中的 `导出发布草稿`。该按钮会把当前角色信息导出为本地轻量 Markdown artifact，标题为 `角色模板发布草稿`，用于把模板状态交给 reviewer 或维护者继续查看。

`角色模板发布草稿` Markdown 会汇总：

- `角色名称` 与基础角色信息。
- `角色设定` 摘要，便于确认角色性格、称呼方式和对话边界是否足够清晰。
- `情绪标签`，用于检查 `sprite` / 情绪编号与文本说明是否对应。
- `示例输出`，保留当前 JSON-lines 示例，方便 reviewer 直接复制到校验器或运行时冒烟。
- `发布前检查` 摘要、状态和修复建议；包含错误、警告以及下一步处理提示。
- 轻量 `角色模板发布清单`，包括 `控制 token 覆盖`，用于快速确认 `NARR`、`CHOICE`、`STAT`、`CG` 等常用控制 token 是否被示例覆盖。

导出行为边界：

- `发布前检查未通过` 时会阻止导出，需先根据修复建议补齐角色名称、角色设定、情绪标签或示例输出中的严重问题。
- `发布前检查有警告` 时允许导出 Markdown，但建议先修正警告，再把 `角色模板发布草稿` 分享给 reviewer/维护者。
- 该草稿是本地轻量 artifact，只用于 reviewer/维护者交接和发布前检查留档；不是完整模板市场、多示例管理或正式发布工作流，也不会自动发布模板。

示例类型选择建议：

- `完整示例`：包含普通角色对话、`NARR`、`CHOICE`、`STAT` 和 `CG`，适合发布前确认模板能覆盖常用控制 token。
- `基础对话`：只包含普通角色对话、`NARR` 和 `CHOICE`，不包含 `STAT` 或 `CG`，适合暂不启用数值提示/CG 的新手或纯对话模板。
- `情绪切换示例`：普通角色多行使用不同 `sprite` / 情绪值，并包含 `NARR`；不包含 `CG`、`STAT` 或 `CHOICE`，适合检查同一角色的立绘/情绪切换写法。
- `CG 示例`：聚焦普通角色对话、`CG` 与 `CHOICE`；`CG` 行的 `speech` 填文生图 prompt，`sprite` 保持 `"-1"`，用于检查 prompt 字段是否放对。
- `剧情分支示例`：包含 `NARR`、普通角色台词、`STAT` 和 `CHOICE`，不包含 `CG`，适合测试剧情分支、线索/好感度变化和 2-4 个分支选项。
- `模板复用示例`：聚焦本地模板库场景，包含 `NARR`、普通角色台词、`STAT` 和 `CHOICE`，适合在导入模板前演练“复核模板包 → 导入模板 → 重新检查并保存配置”的作者路径。
- `模板修正示例`：聚焦发布前检查出现 warning 后的修正流程，包含 `NARR`、普通角色台词、`STAT` 和 `CHOICE`，适合演练“发现 warning → 补齐字段 → 复查后再保存配置”的作者路径。

`填入示例` 和 `发布前检查` 都是本地辅助：它们只读取当前设置页文本并运行本地校验，不调用 LLM，也不调用 ComfyUI 生成图片。示例类型和示例输出属于临时 UI 状态；除非用户把文本复制进模板内容等持久字段，否则点击 `填入示例` 产生的示例不会写入配置，也不会因为 `保存配置` 单独保存为配置项。

### 导出模板发布包

在 `导出发布草稿` 之外，设置页角色管理还提供 `导出发布包`。它会把当前尚未保存也可能尚未持久化的角色模板状态导出为一个本地轻量模板发布包目录，方便 reviewer/维护者复核，也适合发布候选留档。

发布包目录包含：

- `README.md`：发布包入口说明，包含角色名称、导出时间、发布前检查状态、控制 token 覆盖和边界说明。
- `角色模板发布草稿.md`：复用 `导出发布草稿` 的 Markdown 内容，避免草稿格式分叉。
- `template-output.jsonl`：当前 JSON-lines 示例输出，保留原文并补齐末尾换行，便于命令行校验或复制复核。
- `preflight-report.txt`：当前发布前检查摘要，包含错误、警告和 `修复建议：`。
- `metadata.json`：机器可读元数据，包含角色名称、导出时间、发布前检查状态、示例行数和 `NARR` / `CHOICE` / `STAT` / `CG` 控制 token 覆盖。
- `template-data.json`：导入模板库所需的机器可读字段，仅包含角色名称、角色设定、情绪标签和示例输出，不包含私有 API 配置、聊天历史或本机服务配置。

导出行为边界：

- `发布前检查未通过` 时会阻止导出，不会打开目录选择或创建发布包目录。
- `发布前检查有警告` 时允许导出，但结果区域和状态栏会提示建议继续修正。
- 发布包只包含角色模板作者交接需要的本地 artifact；不包含私有 API 配置、LLM/T2I URL、checkpoint、聊天历史或本机服务配置。
- 这是本地轻量模板发布包，不是自动发布、模板市场、多示例管理、审核队列或正式发布工作流，也不会自动上传或发布模板。

### 本地模板库

在已有 `导出发布包` 的基础上，角色管理页还提供 `本地模板库` 工作流，用于把模板作为本地、离线、轻量的复用资源保存和导回当前编辑表单。

可用动作包括：

- `保存到模板库`：把当前通过预检的模板直接保存进 `data/templates/packages/` 下的本地模板库目录。
- `刷新模板库`：重新扫描本地模板库，显示有效和无效模板包。
- `导入选中模板`：把一个可导入模板的角色名称、角色设定、情绪标签和示例输出填回当前编辑表单。
- `打开模板库目录`：打开本地模板库存放目录，便于人工查看和整理。

导入与边界说明：

- 这条工作流是本地、离线、轻量的，不是模板市场、多示例管理或正式发布工作流。
- `保存到模板库` 复用同一套发布前检查：严重错误会阻止保存；只有警告时允许保存，但会提示继续修正。
- `导入选中模板` 会先确认是否覆盖当前编辑字段。
- 导入后会自动重新运行示例输出校验。
- 导入不会直接写入 `characters.yaml`；用户仍需手动点击 `保存配置`。
- 本地模板库和模板包都不包含私有 API 配置、聊天历史或本机服务配置。

## 运行时保护与格式异常提示

发布前校验可以提前发现常见 JSON-lines、必填字段和控制 token 问题，但不能保证模型每次运行都严格按模板输出。如果运行时仍收到无法解析的坏格式结构化回复，程序会安全收住这次回复，在聊天区显示友好的格式异常提示，并提示检查角色模板；不会把原始坏 JSON 或坏结构直接作为角色台词展示。

这个保护只负责避免把异常格式暴露给玩家，不会自动修复所有模板或模型输出问题。遇到提示后，仍建议回到角色模板，检查示例输出、系统提示词和控制 token 写法，再用发布前检查或命令行校验复核。

也可以从项目根使用命令行校验文件或标准输入：

```powershell
venv\Scripts\python.exe scripts\validate_template_output.py path\to\sample.jsonl
Get-Content path\to\sample.jsonl | venv\Scripts\python.exe scripts\validate_template_output.py -
```

## 注意事项

- 不要输出 JSON 外的解释文字。
- 每个对象独占一行。
- 必须包含 `character_name`、`speech`、`sprite` 三个基本字段。
- `CHOICE` 的 `speech` 用 `/` 分隔，建议提供 2-4 个选项。
- `SCENE` 与 `bgm`/`BGM` 仅作兼容解析，聊天运行时不执行；更换背景请使用手动入口。
- `CG` 的 `speech` 填文生图 prompt；不要把 prompt 放进 `sprite`。
- 不确定 token 时优先用普通角色名。
